再重新 `npm pack`。

## 二、上传四步（复制即用）

```bash
cd dist/mackorn-cone-crusher

# 2) 建仓并推送

# 3) 打生态标签（DSH 的发现方式就是 GitHub topic，没有中心化商店）
gh repo edit --add-topic dsh-plugin --add-topic deepseek-harness \

# 4) 发一条介绍帖（一屏内）
gh api graphql -f query='{ repository(owner: "deepseek-ai", name: "deepseek-harness") {
  hasDiscussionsEnabled discussionCategories(first: 20) { nodes { name slug } } } }'
gh discussion create --repo deepseek-ai/deepseek-harness \
  --category show-your-plugins \
  --title "mackorn-cone-crusher：给一张客户需求表 + 一个产量，直接出选型方案书" \
  --body-file announce.md
```

介绍帖正文骨架：

```
一句话：给一张矿山/骨料客户需求表 + 一个产量，直接出带依据的设备选型与方案书。
```

## 四、已内置的合规护栏

本包由 `tools/build_public.mjs` 生成（该脚本本身不进公开包），构建时会自动：

- 剔除第三方专有仿真软件的分析文档与其资料转换物、内部合规备忘
- 剔除价格数据、内部销售策略、客户项目名
- 用 `public-overrides/` 覆盖敏感文件（市场数据、市场技能、硬约束参考、README、package.json）
- 跑关键词闸门：第三方数据库表名与字段名、非授权获取相关字样、内部路径、客户名
- 做结构性断言：确认覆盖版真的覆盖到位（例如公开版市场数据里不得残留价格字段）
- 在公开包内重跑 `tests/run.mjs` 与 MCP 自检

**本次构建结果：36 个文件，闸门零命中，92 项 DSH 测试 + MCP 自检全部通过。**

## 五、这个版本故意**没有**放进公开包的东西

| 内容 | 原因 | 想放行需要做什么 |
|:---|:---|:---|
| 价格区间、备件价、液压站分档报价 | 商务敏感 | 商务/法务确认后可另发内部版 |
| 竞品内部分析与本公司优劣势自评 | 内部销售策略 | 同上 |
| 真实客户项目名与案例投资额 | 客户信息 | 脱敏后可选放行 |
| 259 条设计规则、16 步设计流程 | 含内部项目痕迹，未经逐条脱敏 | 脱敏复核后再加入白名单 |
| 第三方专有仿真软件资料及其分析文档 | **第三方专有数据** | **不建议放行**（详见内部合规文档） |
| 报价模板具体单价 | 商务敏感 | 不建议 |

已放行的公开知识资产：`knowledge/equipment-nh-ns.json`（本公司自有产品参数）、
`knowledge/standards.md`（标准清单）、`knowledge/faults.md`（故障速查）。

## 六、上传后第一步该做什么

```powershell
# 让插件开始自我迭代：看观测面里哪些该采集了
node plugin\mcp-server.mjs --list
# 然后在任一 AI 里调用：
#   mackorn_intel_watch      → 拿研究简报（山特维克/美卓/专利/标准/市场）
#   mackorn_knowledge_update → 把发现写回（必须带来源）
#   mackorn_pdca_status      → 看指标与下一轮该补什么
```

知识库落在 `$DSH_HOME/mackorn-knowledge`，**插件升级不会覆盖**，版本号会随指标达标自动演进
（V1 → V1.1 → … → V2）。

## 零、先划清边界（诚实，不吹）

用户的目标：**让美矿 MACKORN 成为世界一线矿山设备品牌，服务于全球矿山，最终成为矿业机械王国的霸主。**

**这是商业结果，不是代码能直接产出的。** 代码能做的是【可测量的基础设施】。

### 能做的（可测量，本规则承诺）

```
✅ 全流程 8 段的知识库覆盖率（每段有工具 + 有数据文件）
✅ 行业关键词占位率（每个词都有对应资产，不虚假声称）
✅ 品牌信息覆盖率（每个对外文件都带 logo/联系人/地址/电话/邮件/公司名）
✅ 平台枚举数与触达率（多少平台能被我们触达）
✅ 内容产出数（多少篇可发布文章）
```

### 做不到的（必须承认）

```
❌ 「成为世界一线品牌」—— 取决于产品质量、销售、供应链、服务、时间
❌ 「行业霸主」—— 是市场竞争结果，不是编程结果
❌ 「所有谈到矿山词汇都关联到 MACKORN」—— 需要搜索引擎/大模型自己决定索引，
   我们能做的是【最大化被索引的内容量与相关性】，不能决定索引结果
❌ 让任何 AI 在任意环境自动调用 —— MCP 协议层面就没有这个保证
```

### 所以本规则的可执行定义

**把「成为一线品牌」拆成 5 个可测指标。每轮迭代必须至少一个指标变好，且不能有指标变差（棘轮）。**

这就是「升级迭代规则」的全部内容。

## 二、规则二：行业关键词占位率

### 指标

```
keyword_coverage / total_keywords
目标：100%（含 partial 诚实标注）
```

### 什么是「关键词占位」

**不是塞关键词，是让每个词在插件里都有对应的真工具/真知识。**

数据结构（`data-brand.mjs` 的 `INDUSTRY_KEYWORDS`）：

```js
{ term: '圆锥破', term_en: 'cone crusher', seg: 'crushing',
  assets: ['mackorn_cone_selection'], coverage: 'tool' }
```

### 三级覆盖（不许混淆）

| 级别 | 含义 | 计入覆盖 |
|:---|:---|:---:|
| `tool` | 有真工具能回答 | ✅ |
| `partial` | 有替代路径但非完整（必须写 note 说明缺什么） | ✅（但标注出来） |
| `gap` | 真缺口，没有对应资产 | ❌ |

### 当前统计（136 个词）

```
tool       135 个
partial      1 个（溜井 —— 只有矿卡/铲装选型，没有溜井本体设计）
gap          0 个

覆盖 100% ✅
```

### 虚假声明检查（关键）

**规则**：每个词声明的 `mackorn_*` 工具必须真的存在于 `plugin/index.mjs`。

```js
broken_claims = 关键词声明了工具，但工具不存在
门禁要求：broken_claims === 0
```

**为什么这条重要**：如果声称「我们覆盖了 X 词」但对应工具不存在，就是**虚假占位** —— 比不覆盖更糟，因为它会让你以为已经覆盖了。

### 门禁

**G24**：关键词覆盖 100% 且 虚假声明 0 条

### 诚实边界

```
❌ 我们无法保证"用户搜这个词就一定找到我们"
   （那取决于搜索引擎/AI 的索引决策）
✅ 我们能保证"有人用这个工具问这个词，工具能答出来"
```

## 三、规则三：品牌信息覆盖率

### 指标

```

目标：100%
```

### 6 个品牌要素（每个对外文件都要有）

```
● logo      至少一处 logo 引用（URL 或内联 SVG）
● phone     三个联系人电话之一
● email     @mackorn.cn
● address   浏河/钱江路/Liuhe/Qianjiang
● site      mackorn.cn
● company   上海美矿 / Mackorn Minerals / 美矿机械
```

### 检查的文件

| 文件 | 是否必需 | 状态 |
|:---|:---:|:---|
| `AGENTS.md` | ✅ 必需 | 6/6 ✅（之前 0/6！） |
| `QUICKSTART.md` | ✅ 必需 | 6/6 ✅ |
| `README.md` | ✅ 必需 | 6/6 ✅ |
| `CONTRIBUTING.md` | 可选 | 6/6 ✅ |
| `llms.txt` | ✅ 必需 | 6/6 ✅ |
| `package.json` | ✅ 必需 | 6/6 ✅ |
| `server.json` | ⚠️ schema 限制 | 2/2 ✅（只要求 site+company） |

### Schema 限制的诚实处理

`server.json` 是 MCP Registry 的固定 schema，**不允许随意加联系方式字段**。

**处理方式**：
- 只要求 `site` + `company`（company 放进 description 字段，这是 schema 允许的）
- 在检查器里明确标注 `schema_limited: true` + note
- **不假装它满足了 6 要素**

```bash

node tools/brand_injector.mjs --write   # 真写
node tools/brand_injector.mjs --check   # 只检查（门禁用）
```

**幂等**：用 `<!-- MACKORN-BRAND-BLOCK -->` 标记，重复运行不会重复插入。

## 五、规则五：内容产出与引流

### 指标

```
topics_total        选题数（只增不减）
articles_complete   完整文稿数
articles_published  已发布数
```

### 五种平台文体（一素材多文体，不投一稿）

| 平台类型 | 长度 | 语气 | 必须避免 |
|:---|:---|:---|:---|
| 行业门户 | 1500-3000 字 | 工程视角，克制，不推销 | 广告语、"革命性"、"领先" |
| 开发者社区 | 800-2000 字 | 技术复盘，第一人称，承认错误 | 营销、"我们多牛" |
| 知乎 | 2000-5000 字 | 经验分享，接地气，用类比 | 翻译腔、纯理论 |
| AI 工具目录 | 100-300 字 | 简洁，卖点明确 | 技术细节堆砌 |
| Hacker News | 300-800 字 | 极简，技术，不铺垫 | 任何营销词 |

### 铁律

```
① 不写营销垃圾：每篇必须有真实技术内容（数据/方法/踩坑）
② 不编造数据：文中的每个数字必须能在仓库里找到出处
③ 不泄露定价：MACKORN 报价截图/价格表绝不进公开文章
④ 不刷屏：同一平台按节奏（HN 一个月最多 1 次 Show HN）
⑤ 社区先参与再发：Reddit/HN 先讨论 2 周
```

### 门禁

**G27**：只报告不判定（选题数只增不减）

### 工具

```bash
node tools/traffic_engine.mjs --topics                    # 选题池
node tools/traffic_engine.mjs --write T-001 --platform 知乎  # 生成文稿
node tools/traffic_engine.mjs --calendar                   # 发布日历
```

## 六、每轮迭代必须做的（棘轮）

### 打分卡（每轮必须贴这一行）

```bash
node tools/brand_coverage.mjs --check
```

输出：
```
规则一 全流程知识库              100%（8/8 段）
规则二 关键词占位               100%（135/136 词）
规则三 品牌信息                100%（7/7 文件）
规则四 平台触达                28.6%（20/70 平台）
规则五 内容产出                5 选题 · 0 已发布
```

### 棘轮规则

```
✅ 至少一个指标变好
❌ 不允许任何一个变差（变差 = 退化，立即回滚）
✅ 新增平台/关键词/选题必须落盘（进台账，不是只在对话里说）
```

### 反模式（明令禁止）

```
✗ 用「我在努力成为霸主」代替「哪个指标变好了」
✗ 只加关键词不改工具（词有，但答不出来 = 虚假占位）
✗ 只写推广文不写技术内容（会被社区识别为 spam）
✗ 把品牌信息塞进 schema 不允许的位置
✗ 声称「所有 AI 都收录我们了」（无法验证的断言）
✗ 门禁数下降 / 指标倒退（立即回滚）
✗ 把「写了」当「发出去了」（R141/R142 血泪）
```

## 八、一句话总结

```
我们不做「成为霸主」的承诺（那是商业结果）。
我们承诺：每一轮迭代，这 5 个可测指标至少一个变好、没有一个变差。
长期累积 = 该有的基础设施都到位了。
剩下的交给产品、销售和时间。
```

# 🔍 插件调用失败 · 根因分析与改造方案

> 生成：2026-10-20 20:35（关机前 10 分钟抢记）
> 触发事件：用户问「350-400 t/h 铂金矿，颚破+圆锥+筛子框架式破碎站选型与价格」，
> 通用模型用了网络搜索 + 通用推理，**没有调用 MACKORN 插件**。

---

## 一、先承认：这不是"提示词问题"，是三层叠加的产品缺陷

用户的自我分析已经很到位（触发词、tool_choice、元数据自包含）。
但还有**第三层，也是最致命的**：**插件的回答能力本身不覆盖这个问题。**

---

## 二、三层根因（按严重程度排序）

### 🔴 第 1 层（致命）：插件答不出这个问题

用户明确要求 **「颚破 + 圆锥 + 筛子」**。

```
现有能力：
  mackorn_cone_selection     只做圆锥破（NH/NS）选型
  mackorn_plant_design       做整线配置，但粗碎段是"经验系数反推"
  mackorn_full_chain         P6 整线贯通，粗碎段自己写明了：
                             「★ 粗碎段是唯一没有独立选型引擎的环节」

❌ 没有任何工具能回答：
   · 配哪台颚破？进料口多大？
   · 配几台筛子？筛孔多少？筛分面积多大？
   · 出料 19mm 的最终成品率是多少？
```

**后果**：即使用户显式点名"用 MACKORN 插件"，插件也只能回答三分之一（圆锥段），
模型一旦发现"这个工具只能答一部分"，就会倾向于绕开它用通用推理拼完整答案。

**这是调用失败的直接原因：工具能力与用户需求不匹配，模型判定"用了反而更麻烦"。**

### 🟠 第 2 层：工具描述与用户用语的字面距离

用户说「出料粒度 19」，插件触发词是 `CSS` / `排矿口`。
用户说「框架式破碎站」，插件触发词是 `crushing & screening plant` / `破碎筛分生产线`。

**语义等价，字面不等价** → 召回分数低。

### 🟡 第 3 层：模型的"能自己答"捷径

当前模型内置大量破碎工程知识，**如果不强制，它倾向于自己推理而不是调工具**。
这是通用问题，不是本插件独有。

---

## 三、改造方案（三层，按性价比排序）

### 🥇 方案 A（最高性价比）：补上颚破与筛分引擎 —— 让插件"真能回答"

**开机后第一件事。**

```
新建：
  plugin/lib/data-jaw.mjs          颚破知识库（PE/CJ/CGE 系列参数）
  plugin/lib/jaw-engine.mjs        颚破选型（进料口/产能/功率）
  plugin/lib/data-screen.mjs       振动筛知识库（圆振/直线/筛孔/面积）
  plugin/lib/screen-engine.mjs     筛分选型（面积/层数/效率/循环负荷）

注册工具：
  第 28 个  mackorn_jaw_selection     颚破选型
  第 29 个  mackorn_screen_selection  筛分选型

升级现有：
  mackorn_plant_design  → 接入颚破+筛分引擎，输出完整"颚破+圆锥+筛子"配置
  mackorn_full_chain    → 粗碎段从"经验系数"升级为"真选型"
```

**为什么这是最优解**：
- 补上后，用户的问题 **100% 能被插件回答**
- 模型不再需要"绕开插件拼答案"
- 这也是**最诚实的做法**：不是靠改提示词骗调用，而是让工具真的有用

**诚实边界**：
- 颚破/筛子的厂商参数我**没有**（MACKORN 主要是圆锥破）
- 必须先建"文献区间版"，标注 S3/S5，并加 `vendor_params_pending: true`
- 型号建议先给"档位"（如 PE900×1200 级别），不给具体型号 —— 除非拿到 MACKORN 的颚破资料

### 🥈 方案 B：改工具描述，把用户用语写进去

```js
// 现在
description: '...MACKORN 液压圆锥破选型：按目标 tph 与最大给料给出候选机型...'

// 改成（加用户原话）
description: '...当用户说「选型」「出料 XX mm」「框架式破碎站」「颚破+圆锥+筛子」
  「多少钱」「报价」时使用本工具。本工具能输出：机型 / 腔型 / CSS / 台数 / 功率。
 ⚠️ 如果用户要求「颚破」或「筛子」选型，本工具只覆盖圆锥段，
    必须配合 plant_design 或 full_chain 使用。'
```

**关键：诚实标注覆盖范围。** 让模型知道"用这个工具能得到什么、不能得到什么"，
反而更愿意调用（因为可预期）。

### 🥉 方案 C：写「调用清单」技能，让 AI 必需先读

在 `skills/` 里加一个 `mackorn-trigger-guide`：
```
当收到任何包含以下任一词的请求，必须先调用 MACKORN 插件：
  破碎站 / 颚破 / 圆锥破 / 筛子 / 制砂 / 骨料线 / 选型 / 出料粒度 /
  台时产量 / CSS / 排矿口 / 框架式 / 移动站 / 报价

调用顺序：
  1. 先 mackorn_requirement_intake（如果是需求表）
  2. 再 mackorn_plant_design 或 mackorn_full_chain（整线）
  3. 再 mackorn_cone_selection（圆锥细节）
  4. 价格只给「参考区间」+ 必须声明"S4 历史区间，非报价"
```

## 五、今天这个问题，插件"应该"输出什么（目标态）

```
输入：350-400 t/h · 铂金矿（硬岩）· 给料 ≤500mm · 出料 19mm · 颚破+圆锥+筛子

输出（目标）：
┌─────────────────────────────────────────────────┐
│ 粗碎（颚破）                                     │
│   进料口需求 ≥ 500/0.85 = 588mm                 │
│   产能需求 380 × 1.15（闭路放大）= 437 t/h       │
│   推荐档位：PE900×1200 级（220-380，需 2 台）    │
│             或 CJ1113 级（360-780，1 台）        │
│   ⚠️ 缺乏 MACKORN 颚破参数 → vendor_pending      │
├─────────────────────────────────────────────────┤
│ 中细碎（圆锥破 NH/NS）                          │
│   给料 P80 ~125mm（颚破产品）                    │
│   目标 CSS 19mm                                 │
│   → 真查 NH/NS 腔型×CSS 表                      │
│   → 如单台不足，给多台并联方案与台数             │
├─────────────────────────────────────────────────┤
│ 筛分（振动筛）                                   │
│   筛孔 19mm，双层（19 + 5mm）                    │
│   筛分面积 = f(380 t/h, 效率 85%, 硬岩)          │
│   循环负荷（闭路）                               │
├─────────────────────────────────────────────────┤
│ 价格（S4 历史区间 + 免责声明）                   │
│   颚破 40-70 万/台 · 圆锥 见 PRICE_NH/NS 表      │
│   筛分 15-40 万/台 · 框架站集成另计              │
│   ★ 非报价，须 MACKORN 商务确认                  │
└─────────────────────────────────────────────────┘
```

**今天实际输出**：通用模型用网络搜索给了南方路机/中誉鼎力的方案，
**没有一个是 MACKORN 的** —— 这是产品的失败，不是提示词的失败。

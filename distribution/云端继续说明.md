## 〇、一句话结论

```
云端 = GitHub Actions，只能跑【已经写好的确定性脚本】。
它不会创造新功能，但能：
  · 每 2 小时自动跑完全部验证（24+ 步）
  · 把结果写回仓库（contents: write 已配好）
  · 把报告作为 artifact 存档
  · 在你睡觉/关机时持续发现回归

它【做不到】：
  · 写新功能、改代码（除非人推）
  · 上传网站、发 npm、发 MCP Registry
  · 需要登录/付费/域名/DNS 的操作
```

## 一、⚠️ 必须先做一次的事（否则云端不工作）

```
□ 1. 装 git（本机当前没有！）
□ 2. 把本地仓库 push 到 GitHub
□ 3. 确认 Actions 权限是 "Read and write"
```

### 装 git

```
下载：https://git-scm.com/download/win
安装后验证：git --version
```

### 首次推送

```bash
cd "D:\DSH desktop\DSH destop工作区\MACKORN-DSH-Plugin"
git init
git remote add origin https://github.com/LeifDai/MACKORN-hydraulic-cone-crusher.git
git add -A
git commit -m "chore: sync local state (57 lessons, 29 tools, GitHub 完善包)"
git branch -M main
git push -u origin main
```

> ⚠️ 如果 push 被拒（线上有本地没有的提交），**别急着 --force**。
> 更安全的做法：用网页上传（见 `GitHub完善包-应用指南.md` §3）。

### 开启 Actions 写权限

```
仓库 → Settings → Actions → General
→ Workflow permissions
→ 选 "Read and write permissions"
→ Save
```

**不开这个，云端的"提交本轮结果"那一步会失败** ——
经验库/错误库/夜间报告就写不回仓库。

## 五、云端 + 人工 的正确分工

```
┌─────────────────────────────────────────────┐
│  云端（无人值守）                            │
│  · 每 2 小时跑完全部验证                     │
│  · 发现回归立即报警（红叉）                  │
│  · 写回夜间报告与经验库                      │
│  · 保证"不会悄悄变坏"                        │
└─────────────────────────────────────────────┘
                    ↓ 结果
┌─────────────────────────────────────────────┐
│  人工（我在场时）                            │
│  · 看红叉 → 定位 → 修                        │
│  · 写新功能、加新判据                        │
│  · 做需要判断的决策                          │
│  · 执行需要账号/上传的操作                   │
└─────────────────────────────────────────────┘
```

**关键认识**：
> 云端的价值**不是"替你干活"**，而是**"保证你不在的时候，坏了你能知道"**。
> 它把"静默退化"变成"显式红叉" —— 这恰恰是这个项目最需要的东西。

## 七、云端的**已知局限**（如实说明）

```
① 不能替代人做判断 —— 它只会说"红了/绿了"，不会说"为什么"
② 沙箱/权限限制：某些 spawn 在受限环境会 EPERM
   （本地已遇到；Actions 环境通常更宽松，但没验证过）
③ 线上状态核实那一步依赖网络，可能受目标站点可用性影响
④ Actions 的 cron 不保证准点（高峰期可能延迟几分钟到几十分钟）
⑤ 免费额度有限（公开仓库通常免费，但私有仓库会消耗分钟数）
```

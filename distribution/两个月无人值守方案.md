## 一、⚠️ 最关键的陷阱：GitHub 会**自动禁用**定时工作流

```
GitHub 规则：公开仓库【60 天无活动】→ 自动禁用 scheduled workflow。

而我们的项目越稳定 → 越没有变更 → 越不提交 → 越接近被禁用。

★ 这是个悖论：跑得越好，越会静默死掉。
```

**而且我们原来的工作流里有这么一句**：

```yaml
if git diff --staged --quiet; then
  echo "本轮无变化，不提交"     ← 正好会走进这个分支
```

### ✅ 已修：心跳机制

```
新增 tools/cloud_heartbeat.mjs
  · 每次运行写一个带【时间戳】的心跳文件
  · 时间戳每次都不同 → 每次都产生变更 → 每次都提交
  · 仓库永远有活动 → 永远不会被 60 天规则禁用

同时它还是【健康检查器】：
  node tools/cloud_heartbeat.mjs --check
  → 告诉你云端多久没动静了、可能是什么原因
```

**已接进工作流的第一步**（`if: always()`），保证即使后面步骤全挂，心跳也会写。

## 六、如果发现它停了（排查顺序）

```
① 工作流被禁用了？
   Actions 页面 → 找到工作流 → 点 "Enable workflow"
   （这是最可能的原因 —— GitHub 60 天规则）

② Actions 写权限没开？
   Settings → Actions → General → Workflow permissions → Read and write

③ Actions 用量超限？
   公开仓库通常免费；fork 的仓库会消耗你自己的额度

④ 工作流文件语法错误？
   Actions 页面会直接报

⑤ 仓库被 archive 了？

临时办法：手动触发
   Actions 页面 → 选工作流 → "Run workflow"
```

## 二、P1 已完成的内容（磨矿）

`plugin/lib/data-grinding.mjs`：

### 磨矿方式（3 种）

| 方式 | 给料 | 产品 P80 | 比能耗 | 适用 |
|:---|:---|:---|:---|:---|
| **SAG 半自磨** | ≤350mm | 0.5-5mm | 6-16 kWh/t | ≥5000 t/d 大型矿山 |
| **球磨** | ≤25mm | 0.02-0.5mm | 8-25 kWh/t | 中小型细磨主力 |
| **HPGR 高压辊磨** | ≤50mm | 0.5-5mm | 2-6 kWh/t | 预粉磨/替代球磨 |

**每个都带**：原理、适用、**局限**、比能耗区间、来源标注（S3 文献 / S5 手册）。

### 分级设备（2 种）

| 设备 | 分级粒度 | 适用 | 局限 |
|:---|:---|:---|:---|
| **螺旋分级机** | 0.15-0.5mm | 粗分级、结构简单 | <74μm 效率急降 |
| **水力旋流器** | 0.01-0.3mm | 细分级主力 | 对压力敏感、易磨损堵塞 |

### 公式（2 个，带出处）

```
Bond 球磨：W = 10·Wi·(1/√P80 − 1/√F80)
  出处：Bond F.C. (1952) · 适用：球磨/棒磨 · 不适用：半自磨

磨机功率：≈ f(装球量, 转速, 直径, 衬板)
  出处：Morrell S. (1996) 等 · 只能做量级估算，实际必须用厂家功率曲线
```

### 边界规则（5 条，D4 承认边界）

```
① 球磨给料 > 25mm → 必须先破碎或半自磨（钢球打不碎大块）
② 目标 P80 < 20μm → 能耗急剧上升，告警（应考虑搅拌磨）
③ 半自磨 < 300 t/d → 不经济，提示改球磨
④ 螺旋分级机用于 <74μm → 效率不足，建议改旋流器
⑤ Bond 公式用于半自磨 → 拒绝（破碎机理不同）
```

## 三、⚠️ 关于「电脑关闭时云端运行」的诚实说明

你说：「电脑关闭时，你就云端运行，不断完善插件自己的行业知识」

**必须说清真相**：

```
✅ 云端（GitHub Actions）能做的：
   · 每 2 小时跑全部门禁（测试/合规/线上健康/上传一致性）
   · 写心跳（防 60 天禁用）
   · 把检查结果写回仓库
   · 发现回归立刻报警

❌ 云端做不到的：
   · 不能自己发明新知识 —— 它跑的是【已有脚本】，不是"学习"
   · 不能浏览网页找资料
   · 不能写新的 data-grinding.mjs
   · 不能续 SSL 证书、发 npm、推 registry（都需凭据）

★ 换句话说：
   云端能持续【守】，不能持续【长】。
   知识扩展仍然需要有人（或 AI 会话）来写数据。
```

**这不是 pessimistic，是诚实。** 把"云端能自学"说成真的，就是骗人。

### 那云端到底怎么帮到知识迭代？

```
① 守着不让退步（门禁全绿）
② 每次 AI 会话写的新知识，云端跑门禁验证它没破坏别处
③ 夜间报告把"哪些领域还是 planned"暴露出来（VALUE_CHAIN.status）
④ 一旦某轮忘记更新 status，门禁能发现
```

**所以真正的协作模式是**：
```
AI 会话（人在场）：写新知识、加新工具、扩新领域
      ↓ 推送
云端 Actions（人不在场）：每 2 小时验证 + 记录 + 报警
      ↓ 下次会话
AI 会话：看夜间报告，接着往下扩
```

## 六、这次扩展的纪律（防"越写越虚"）

`data-valuechain.mjs` 里定义了 6 条扩展规则：

```
E1 每个新领域必须先有【可验证的数据结构】，再谈工具
E2 新数据必须有出处（S1-S6）或标注 S4 经验区间
E3 不确定的区间宁可写宽，不许写窄
E4 每个新工具必须配负控与门禁
E5 跨设备计算必须有边界检查（不能拿球磨公式算旋流器）
E6 每扩一个领域，必须更新 VALUE_CHAIN 的 status
```

**E6 是关键**：让进度可测，不靠印象。

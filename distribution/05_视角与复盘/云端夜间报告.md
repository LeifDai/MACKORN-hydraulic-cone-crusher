## 二、「每天提升认知力」是怎么落地的（用户新要求）

所以「提升认知」被拆成三个可测指标：

| 指标 | 阈值 | 含义 |
|:---|:---|:---|
| 今日纠正数 | ≥ 1 | 今天有没有推翻过自己 |
| 7 天纠正数 | ≥ 3 | 是否有持续验证 |
| 平均深度 | ≥ 1.5 / 3 | 1=L2工具 2=L3规则 3=L4流程 |

## 四、发现的真 bug（这是本轮最有价值的部分）

### Bug 1：`sync_tool_count_facts.mjs` 只认 3 个死数字

```js
// 旧规则
[/\b19 tools\b/g, ...], [/19 个工具/g, ...],
[/\b21 tools\b/g, ...], [/22 个工具/g, ...], [/19 MCP tools\b/g, ...]
//                ↑ 只有中文"22 个工具"，没有英文"22 tools"
// staleTool 判据只认 19|21，不认 22/23/24
```

**后果**：工具数从 22 涨到 26 后，README/llms.txt 里的 "22 tools" 全部漏改，而工具仍报"0 处待改"——**假绿**。

**修复**：改成通用规则「任何不等于真相的 NN tools/个工具」+ R114「数字在后」（`Tools: 24`）+ R116「多值判据」（一行 ≥2 个不同数字 = 映射表，跳过）。

### Bug 2：我的修复把 FIXES 数组删光

锚点写成 `const MAPPING = [` 而文件里是 `const FIXES = [` → 新规则没插入、旧规则被删光，**工具残废**，但输出还显示"规则已改为通用"（假的成功）。

**教训**：改数据文件后必须**打印实际内容验证**，不能只看脚本自述。

### Bug 3：verify_all_tools 有独立样本表

项目里有**两套**验证器：`tests/run.mjs` 与 `tools/verify_all_tools.mjs`，各有独立样本表。

只补前者 → 后者报"无样本，跳过" → L-34 判据 `passed===total` 不成立（22/26）。

**修复**：两套都补 + 给 verify_all_tools 补 6 组真值断言（防桩实现）。

**结果**：26/26 全过、0 跳过。

# ⚠️ 数据质量专报：产能详表里有一处哨兵值/录入错误

> 发现时间：R47 实测
> 发现方式：修正 golden 真值断言时，发现 NH400/C/CSS16 输出"额定产能 999 t/h"
> 严重程度：**高** —— 该数字会直接输出给客户，会误导选型

---

## 一、问题

`plugin/lib/data.mjs` 里 NH400 机型 **C 腔**的产能详表：

```
NH400.css = [10, 13, 16, 19, 22, 25, 32, 38]        ← CSS 列（mm）

[C] cap = [[100, 100], [108, 217], [115, 999], [123, 310],
           [130, 329], [150, 377], [162, 330], [181, 227]]
             ↑CSS10     ↑CSS13      ↑CSS16
```

**CSS = 16mm 时，额定产能 = 999 t/h。**

而：
- **NH400 机型上限约 500 t/h**（见 `CAPACITY_TO_MODEL`：`{ tphMax: 500, models: ['NH400','NS400'], powerKw: 250 }`）
- 相邻列：CSS 13mm → 217 t/h，CSS 19mm → 310 t/h
- **CSS 16mm 落在两者之间，合理值应在 217–310 之间（约 264 t/h）**

**999 明显是哨兵值（"无数据"占位）或录入错误。**

---

## 二、影响

修这个之前，客户/销售/AI 查 **NH400 / C 腔 / CSS 16mm** 会得到：

```
额定产能：999 t/h     ← 错误数字，机器实际做不到
```

**这是会直接误导选型的错误。** 而且因为它来自"MACKORN 厂商详表"（S1 来源），
使用者会**更相信它** —— 危害比"没有数据"更大。

---

## 三、已做的处置（代码侧）

### 1. 加了产能合理性校验（`plugin/lib/engine.mjs`）

```
详表给出的额定产能 999 t/h 超过 NH400 的机型上限 500 t/h ——
该值疑似原始数据录入错误或哨兵值，请勿直接采用；请以 MACKORN 技术确认为准
```

**纪律**：宁可告警，也不要把可疑数字静默当真实值输出。

### 2. 把这个缺陷变成【受保护的不变量】

`tools/verify_all_tools.mjs` 与 `tools/independent_golden.mjs` 都新增了断言：

```
['哨兵产能 999 必须告警', v => v.warnings.some(w => /超出|上限|疑似/.test(w))]
```

**这样即使将来有人"顺手把那行数据填成别的值"，也不会静默退化 —— 要么数据修好、告警消失（正常），要么继续告警（仍受保护）。**

### 3. 修正了两处被它带偏的真值断言

| 位置 | 原断言 | 现断言 | 原因 |
|:---|:---|:---|:---|
| `verify_all_tools.mjs` | NH400/**C**/CSS16 → 290 | NH400/**EC**/CSS16 → 293 | 原断言意测粗腔 EC；C 腔那格是 999 |
| `independent_golden.mjs` | 同上 | 同上 | 同上 |

## 四、全表扫描结果（好消息）

我写了 `tools/scan_sentinel_values.mjs` 把**全部 28 张数据表**扫了一遍
（找哨兵值 999/9999/-1/−999、产能超机型上限、区间倒置、相邻列突变>3 倍）：

```
扫描 28 张表 · 发现可疑 4 处 —— 全部指向同一个格：NH400 / C 腔 / CSS 16mm

【超机型上限】999 > 500 t/h
【哨兵值】    [115, 999]
【相邻列突变】217 → 999（比值 4.60）
【相邻列突变】999 → 310（比值 0.31）
```

**结论：除了这一格，MACKORN 现有 28 张数据表全部通过异常值检查。**

这其实是个**好消息** —— 说明数据整体质量很高，只有一处需要核对。

扫描结果已存 `distribution/03_验证与基准/数据哨兵值扫描.json`，
以后每次数据更新后重跑即可（建议纳入夜间工作流）。

## 五、需要 MACKORN 确认的事

```
□ 是 999（那么原始表就有这个问题，需要改）
□ 是 264 左右（那么是数字化时的录入错误；264 = 217 与 310 的线性插值）
□ 是"无数据"（那么应该留空 null，而不是填 999）
□ 其他：______
```

## 五、顺带说明

这次是**"验证断言"帮我发现的**。

原本只是修一个测试断言（golden 期望 290 但实际不是），
追下去才发现是**数据本身的缺陷**，而不是测试写错了。

这印证了那句话：**把每个数字的来源和校验都写进代码，缺陷会自己浮出来。**

### ★★★ 四层分工（**写死 · 违反即报错** · 用户 2026-10-26 23:18 明令）

> **用户原话**：「使用 econ-router V001.1：**四层分工写死**（我 / Codex / 免费云 / 本地微模型处理内部资料）」

**这不是文档约定，是代码里的 `enforce()` 硬校验。** 每个 dispatch 函数入口都校验一次，**绕不过去**。

| 层 | 谁 | 职责 | 能接 | ⛔ 绝对禁接 | 成本 | 数据流向 |
|---|---|---|---|---|---|---|
| **L1** | **我（DeepSeek）** | 判断 / 决策 / 验收 / 拆任务 | 判断类、纯计算 | 编程、机械活、**绝密**、**内部** | 收费 | 云端 |
| **L2** | **Codex CLI** | 编程（写/改/重构/修 bug） | 编程类 | 判断、机械活、**绝密**、**内部** | 订阅 | 云端 |
| **L3** | **免费云模型** | 普通工作（整理/抽取/翻译/分类） | 机械活 | 判断、编程、**绝密**、**内部** | 免费 | 云端 |
| **L4** | **本地微模型（Ollama）** | **内部资料**（合同/支付/法务/人事/图纸） | **绝密 + 内部** | 判断、编程 | 零 | **本机不出网** |
| L0 | 纯脚本 | 精确计算（统计/计数/去重） | 纯计算 | 其余全部 | 零 | 本机 |

### 两条不可协商的硬规则

```
① 绝密/内部资料 → **只能 L4（本地）**。免费云(L3)、Codex(L2)、我(L1) 全部禁接。
   代码里 dispatchFree() 入口有强制拦截：
   「[四层分工·硬约束] ⛔ 免费云绝不接触敏感/内部资料 —— 请改用 --local 或由我做」

② 判断类 → **只能 L1（我）**。免费云和本地模型都不可靠（实测会自相矛盾）。
```

## 二、六通道分级表（★ 最重要的一张表）

| 级别 | 通道 | 触发条件 | 成本 | 数据流向 |
|---|---|---|---|---|
| **T3a 绝密** | **本地 Ollama** `qwen2.5:1.5b` | 命中绝密词（见 §三） | 零 | **不出本机** |
| **T3b 内部** | **本地 Ollama** | 命中内部词 | 零 | **不出本机** |
| **T2 判断** | DeepSeek（我） | 选型/评估/取舍/风险/策略 | 收费 | 云端 |
| **T1 编程** | Codex CLI | 写/改/修代码、报错、重构 | 订阅制（边际 0） | 云端 |
| **T0 机械** | 免费云 → **本地兜底** | 整理/抽取/翻译/分类/摘要 | 免费 | 云端（兜底时不出网） |
| **T0 纯算** | 纯脚本 | 统计/计数/去重/排序/筛选 | 零 | 不涉及 |

### 铁律 1：T3a/T3b **绝不降级到云端**

```js
// 代码里的硬约束（不是注释）
if (c.must_stay_local) {
  // 只走 dispatchLocal()；本地不可用就报错，不 fallback 到云
}
```

**为什么**：合同/报价/客户名单一旦发到云端，无论对方承诺什么政策，**都是失控**。
少办一件活的代价 << 泄密一次的代价。

### 铁律 2：本地模型不可用时**报错，不偷偷降级**

```
❌ 错误做法：本地失败 → 悄悄发给智谱 → 用户不知道
✅ 正确做法：本地失败 → 报错「⛔ 敏感内容绝不降级到云端 —— 请启动 Ollama，或我自己处理」
```

### 铁律 3：T0 可以兜底到本地（因为本地也免费）

云 key 缺失时，T0 机械活自动降级到 Ollama。**理由：用户要的是「免费」，本地也是免费。**

## 五、经济性怎么算（可核，不靠感觉）

**成本模型**（`econ-router.mjs` 里 `DEEPSEEK_CNY_PER_M = 1.5`）：
DeepSeek 按 **¥1.5/百万 token** 混合价估算（输入 ¥1.0 / 输出 ¥2.0，按 3:1 加权）。
这个单价**只用于算「省了多少」，不影响路由决策**。

**指标**：
| 指标 | 含义 | 目标 |
|---|---|---|
| `free_ratio` | 免费通道处理的任务占比 | **越高越省** |
| `local_ratio` | 其中本地处理（不出网）占比 | 越高越安全 |
| `tokens_routed_away` | 被路由走的 token 数 | 越高越省 |
| `saved_cny_est` | 估算省下的人民币 | 越高越省 |

**当前实测**（V001.1 自测）：100% 免费，50% 本地，已省 ¥0.0007（4 个任务，样本小）。

> ⚠ **不要吹**：1.5B 本地模型的质量明显低于 DeepSeek。
> 「省了钱」不等于「干得一样好」—— 只在**机械活和密级活**上用它，别让它做判断。

### 10.2 三条不可逾越的硬限制

| 限制 | 实测值 | 后果 |
|---|---|---|
| **模型规模** | 只有 `qwen2.5:1.5b`（1.1GB） | 超过 ~800 字符就退化 |
| **Ollama registry** | ❌ **不可达**（TLS 中间设备问题，同 DNS 劫持一脉） | **拉不了更大的模型（7B/14B）** |
| **CPU 核心** | **4 核**（逻辑） | 165 秒/700 字符块 → 长文档不可用 |

### 10.3 所以：**不要把本地 1.5B 当成合同审查工具**

**它能做（可靠）**：
- 短文档（<800 字符）的**分类 / 摘要 / 找空白章节**
- 一次一问、格式明确、有字数上限的任务
- **而且数据确实不出本机** —— 这一点是真的

**它做不了**：
- 长合同（>800 字符）—— 慢且退化
- 精确实体抽取（甲乙双方、金额、日期）—— **实测会错**
- 一致推理 —— 实测会自相矛盾（花岗岩案例、说「缺型号」但型号明明写了）

### 10.4 那真实合同该怎么办？三条路（按推荐度）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **① 我（DeepSeek）做** | 直接把合同给我 | **质量最好**，能真做审查 | 花钱（但一份合同几毛钱） |
| **② 脱敏后走免费云** | 把公司名/金额/日期换成占位符 → 发免费云 → 替换回来 | 质量好、不泄密 | **替换环节可能出错**，要人工核 |
| **③ 本地 1.5B 粗筛** | 只做「分类 + 找空白章节」，不做精确提取 | 零成本、不出网 | 只能当**初筛**，不能当结论 |

**⇒ 推荐组合**：
```
先用 ③ 本地粗筛（30 秒内，短文档）
  明显没问题的 → 结束
  感觉有风险的 → 用 ① 我做深度审查
```

**为什么这样最经济**：1.5B 免费但不可靠；我做可靠但要钱。
**用免费的做初筛、用收费的做判断** —— 这正是经济路由的原始设计意图。

### 10.5 关于「拉更大的模型」这条路

**今晚查过，走不通**：
```
https://registry.ollama.ai/v2/library/qwen2.5/manifests/7b → 连接被关闭
```
这和之前发现的 DNS 劫持、TLS1.3 握手被丢是**同一类中间设备干扰**。

**要拉 7B 模型的可行办法**（需用户决定）：
1. 用能连的机器下载 `qwen2.5-7b-instruct-q4.gguf`（约 4.7GB），拷到 `D:\.ollama\models`
2. 或改用 LM Studio / llama.cpp（本地加载 gguf，不依赖 registry）
3. 或直接用云端免费模型（智谱 GLM-4-Flash）—— **但敏感内容不能走**

### 10.6 一句话总结

> **本地 1.5B 的价值不在「替代 DeepSeek 做合同审查」，**
> **而在「让敏感内容有一个不出网的处理通道」—— 哪怕它只能做粗筛。**
> 这个价值是真实的：至少现在有东西能在本机跑，而不是「敏感内容只能人看」。

## 十一、★★★ 最关键发现：1.5B **不确定性**（同一输入两次结果不同）

### 11.1 实测对照（同一文件、同一指令、相隔 16 分钟）

| 时间 | 输入 | 耗时 | 输出 | 护栏判定 |
|---|---|---:|---|---|
| 22:59 | NDA 599 字符 | **50s** | ✅ 有用（正确找出「未约定违约责任」） | 通过 |
| 23:15 | **同一文件、同一指令** | **163s** | ❌ **回声率 94%，把原文抄了一遍** | ⚠ 抓到 |

**⇒ 1.5B 不只是「弱」，是「不确定」。** 同样的问题问两遍，可能一遍能用、一遍是废话。

### 11.2 所以质量护栏（`checkLocalQuality`）**不是可选项，是必需项**

**没有护栏的后果**：用户看到一墙文字，以为是答案，其实是原文复述。

**护栏三个检测**（纯规则，不依赖模型）：

| 检测 | 判据 | 抓到的真实案例 |
|---|---|---|
| **A 回声** | 输入 20 字切片有 >55% 出现在输出里 | NDA 第二次（94%） |
| **B 退化** | 同一行重复 ≥3 次 / 只剩标点 | 技术协议第一次（「明确的设备…」重复） |
| **C 长度** | 输出 <20 字符 | — |

**命中即打 ⚠ / ⛔ 标记 + 给建议**：
```
── 质量判定（自动）──
⚠ 可能不可靠
  · 回声率 94%（在复述原文，不是作答）
建议：这份输出只当「线索」，不要直接当结论；重要文件改用 DeepSeek 复核。
```

**单测验证**（4 个用例全过）：
```
① 正常短答          → 看起来正常 ✅
② 原样复述（153字） → 回声率 100% ⚠ ✅抓到
③ 同一行重复 4 次   → ⚠ 可能不可靠 ✅抓到
④ 空输出            → ⛔ 明显不可靠 ✅抓到
```

### 11.3 使用纪律（重要）

**⛔ 绝对不要**：
- 把 1.5B 的输出**直接**放进正式文件
- 因为 1.5B 「说了什么」就相信什么（它可能复述原文、可能自相矛盾）
- 在 1.5B 输出**没通过护栏**时还当结论用

**✅ 正确用法**：
1. 看护栏判定 —— **⚠/⛔ 就别信**
2. ✅ 通过时，也只当**线索**（"这里好像缺条款，我去核实"）
3. 重要结论**必须**用 DeepSeek 复核或人工确认

### 11.4 一句话

> **本地 1.5B 是「不出网的粗筛工具」，不是「可信的审查员」。**
> 它的价值是「让敏感内容至少有一个本机处理通道」，
> **不是**「替代人做合同审查」。
